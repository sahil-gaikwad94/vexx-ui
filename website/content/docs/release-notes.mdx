**Vexx 2.1 is the standalone release.** It ports the newer neuro-symbolic code engine — previously
embedded in Maya250M as "Vexx 3.5" — into the standalone Vexx repository, with additional hardening
and corrections. Maya250M was a source of features, not a runtime dependency.

Version alignment is exact: the Python package and the Rust workspace are both **2.1.0**. The 1.5
history is kept in the repository's `docs/1.5-release.md`.

Vexx 2.1 is also integrated into two maya labs. products: **maya250M**, a small language model for
coding and reasoning, and **MayaWorkbench**, an AI research and engineering workbench for P2C
workflows. The library remains standalone; those integrations are consumers of it, not dependencies.

If you only read one line: **the library now verifies generated code as well as generated JSON, and
every result can explain how much the constraints changed the model's distribution.**

## The headline: a code-generation and research-verification engine

A new modular subsystem under `python/vexx/code_engine/`, plus `cas.py`, `calibration.py`,
`cache_protocol.py`, `rl/code_rewards.py` and `bridges/code_hf.py`:

- **Incremental lexer** (`LexerState`, `advance_lexer_state`) with PEP 701 nested f-string support.
- **Live callable contracts** (`ParameterContract`, `CallableContract`, `check_call`,
  `build_contracts`, `header_contract_from_text`) that verify arguments as calls are decoded.
- **Tier-0 / Tier-1 masking** (`VexxCodeController.mask_logits`, `filter_draft_tokens`) with token-id
  validation, sparse-vocabulary support and a typed `DeadEnd` when every candidate is masked.
- **Safe symbolic CAS** (`safe_sympy`, `crane_cas_evaluate`, `solve_linear_system`,
  `integrate_definite`, `modular_pow`) behind the optional `.[cas]` extra.
- **Rational single-row conflict contractor** (`contract_single_row`) with explicit relation
  direction and generic cache adapters.
- **Statistical, dimensional and epistemic diagnostics** (`verify_statistical_report`,
  `verify_epistemic_calibration`, `parse_unit_dimensions`) with corrected GRIM rounding intervals and
  Student-t handling.
- **Isolated subprocess sandbox** (`SandboxRunner`) with honest `network_isolated` reporting — it
  never falls back to in-process `exec`.
- **Multi-cell experiments** (`ExperimentEpisode`) with bounded preambles.
- **Candidate verification**, empirical consensus selection (`select_candidate`), differential
  fuzzing (`fuzz_against_oracle`), RLVR rewards and atomic DPO export.
- **Hugging Face code logits processor** (`VexxCodeLogitsProcessor`).

## Corrections over the reference implementation

These are the differences that make the standalone release safe to document:

- Nested f-string quote handling no longer rejects valid nested string literals.
- Session-isolated symbol tables are keyed by a collision-resistant digest.
- Tokenizer ids are validated — no negative indexing, sparse vocabularies handled explicitly.
- CAS is optional and bounded; a base `import vexx` works without SymPy or NumPy.
- GRIM compares against the rounding interval implied by the printed precision.
- The t-test uses real Student-t when available; `z` is two-sided only when declared.
- Cache rewind sits behind a protocol and recurrent state fails closed.
- The sandbox never claims network isolation it cannot enforce.
- Speculative filtering is documented as syntax-only prefix filtering, not a parallel tree verifier.
- Consensus selection is documented as **empirical** consensus, not formal MBR.
- RLVR rewards are not claimed to be reward-hacking-proof.

## Carried forward from the 1.5 hardening line

The earlier engine layer is unchanged in 2.1 and still covered by its tests:

- Per-field **KL-distortion receipts**. At every sampled step the distortion from hard masking is
  exactly `−log(P_raw(allowed))`, tracked per field and per step and bundled into `result.receipt()`.
- The **MCP firewall** (`VexxMcpSession`, `@verified_tool`): LTLf temporal masking of tool picks,
  symbolic `last_*` environment binding, spend caps, taint tracking on untrusted strings.
- **`vexx serve`**: an OpenAI-compatible `/v1/chat/completions` proxy. Non-streaming responses are
  re-verified (422 on violation); streaming responses carry a `vexx_certificate` event before close.
- **`vexx explain-unsat`**: per-clause minimal widening or raising, or a straight answer that the
  conflict is structural.
- **`vexx export-rl`**: DPO/GRPO JSONL with SHA-256 manifests from decoder traces.
- Soundness fixes for indefinite quadratic forms, word-boundary regexes and Fourier–Motzkin pruning.

## Verification status

- **425 Python tests pass** in the default suite; 41 native-parity tests skip unless the wheel is built.
- **69 Rust unit tests** plus **12 property tests** in `crates/vexx-core/tests/soundness.rs`.
- CI runs `cargo test`, `clippy -D warnings`, the pyo3 build and the wasm build.

## Known limitations, honestly

- Rust/WASM acceleration is unchanged for existing JSON-mask semantics; the new code engine ships in
  pure Python first.
- Sandbox network isolation depends on the host OS or container and is reported honestly per run.
- CAS CPU protection uses operation and size bounds, not an in-process timeout.
- Statistical diagnostics return `UNKNOWN` when evidence is insufficient.
- No benchmark numbers are claimed from unit tests.
